# DyV (Dynamic Video) 格式规范 v1.0

## 1. 概述与设计理念

传统视频编码标准（如 H.264/AVC, H.265/HEVC, VP9, AV1 等）主要针对自然连续动态视频（如电影、电视）进行优化，采用固定宏块、运动矢量搜索与严格的恒定/近似恒定帧率机制。在面对**屏幕录制、UI 交互、仪表盘监控、终端打字、低功耗物联网显示、远程桌面**等场景时，存在明显的结构性缺陷：

1. **固定全屏刷新开销**：传统格式即使只有画面中几个像素的鼠标指针或打字光标在移动，编码器仍需对全画面的宏块进行预测、残差变换和环路滤波，浪费大量 CPU 算力和码率。
2. **缺乏真正的弹性动态帧率**：传统视频容器虽可通过包时间戳实现 VFR，但解码器内部管线高度依赖帧率缓存（DPB），在静止 5 秒后突然需要 120 FPS 的突发动效时，极易产生卡顿或必须塞入大量冗余恒定重复帧。
3. **解码算力与显存门槛高**：嵌入式设备、低功耗 MCU 或轻量级 Web/Canvas 应用无法低开销直接提取局部的脏区域进行增量贴图。

**DyV (Dynamic Video)** 是专门为高效储存、极低冗余与广泛适应性而设计的新型轻量级动态视频格式。其两大核心基石为：
- **原生动态帧率 (Native Variable Frame Rate, VFR)**：基于高精度 Timescale + PTS，画面静止时零开销挂起，发生变动时瞬间毫秒级响应。
- **几何级局部刷新 (Area-based Partial Refresh)**：**当画面中只有一部分面积的内容发生变化时，在下一帧只保存变化区域的画面数据**，解码端直接覆盖局部参考画布，实现高达 90%~99% 的带宽与储存空间节省。

## 2. 核心架构与术语

- **参考画布 (Reference Canvas)**：解码器在内存中维护的当前完整画面缓冲区，尺寸为 `Width × Height × Channels`。
- **时间基 (Timescale)**：每秒的时钟滴答数（Ticks per Second）。例如 `Timescale = 1000` 表示 1 tick = 1 毫秒；`Timescale = 1000000` 表示微秒级精度。
- **显示时间戳 (PTS, Presentation Time Stamp)**：以 Timescale ticks 计量的绝对播放时间。两帧之间的时间差 `Δt = (PTS_next - PTS_curr) / Timescale` 可任意缩放。
- **脏矩形 (Dirty Rect / Region)**：画面在相邻帧之间发生变化的最小外接矩形 `(x, y, w, h)`。
- **瓦片网格 (Tile Grid)**：将画面划分为固定大小的瓦片矩阵（如 `64×64` 像素）。
- **空帧 (Empty Frame)**：画面完全无变化时仅用于推进时间轴的标记包，开销仅 2~3 字节。

## 3. 文件二进制结构

所有多字节字段均采用**小端字节序 (Little-Endian)**。变长无符号整数采用标准 **LEB128 无符号 Varint**（最高位 1 表示后续有字节，低 7 位为有效数值）。

```
+--------------------------------------------------------------+
| Header (固定 26 字节 + 可变长度元数据盒 TLV)                   |
+--------------------------------------------------------------+
| Frame 0 (关键帧 KEY, 包含全部瓦片)                           |
+--------------------------------------------------------------+
| Frame 1..n (增量帧 / 关键帧)                                 |
|   - DELTA_RECTS (脏矩形刷新: 仅存 (x,y,w,h) 及该区域数据)      |
|   - DELTA_TILES (瓦片局部刷新: 仅存变化的瓦片索引与数据)        |
|   - EMPTY       (空帧: 零图像数据，仅推移时间戳 PTS)         |
+--------------------------------------------------------------+
| 0xFF (帧流终止哨兵字节)                                      |
+--------------------------------------------------------------+
| Trailer 元数据盒 (TLV, 以 0x00 字节结尾)                     |
+--------------------------------------------------------------+
| [可选] 关键帧索引表 (Keyframe Index Table)                    |
+--------------------------------------------------------------+
| Tail (total_frames: u64, index_offset: u64, 'DYVE': 4字节魔数) |
+--------------------------------------------------------------+
```

### 3.1 文件头 (Header)

| 偏移 | 字段名 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| 0x00 | `magic` | 4 字节 | 固定为 ASCII 字符串 `"DYV "` (0x44, 0x59, 0x56, 0x20) |
| 0x04 | `version` | u8 | 规范版本号，当前为 `1` |
| 0x05 | `profile` | u8 | `0` = 无损 (Lossless), `1` = 有损 (Lossy) |
| 0x06 | `flags` | u16 | 位标志：Bit 0 (`1<<0`) = 包含尾部索引；Bit 1 = 循环播放；Bit 2 = 包含 CRC32 校验；Bit 3 = 包含音频轨 |
| 0x08 | `width` | u32 | 画面宽度（像素） |
| 0x0C | `height` | u32 | 画面高度（像素） |
| 0x10 | `tile_size` | u16 | 瓦片尺寸（如 32, 64），边缘自动截断 |
| 0x12 | `timescale` | u32 | 时间基（每秒 ticks 数，如 1000） |
| 0x16 | `pixel_format` | u8 | `0` = RGB24 (3通道), `1` = RGBA32 (4通道), `2` = GRAY8 (单通道灰度), `3` = GRAY8A (灰度+透明) |
| 0x17 | `tile_codec` | u8 | 瓦片压缩算法（0=RAW, 1=ZLIB, 2=ZSTD, 3=JPEG, 4=WEBP） |
| 0x18 | `transform` | u8 | 预处理变换（0=无变换, 1=XOR Delta 残差变换） |
| 0x19 | `reserved` | u8 | 保留字节，写入 0 |

紧随其后为 **Header 元数据盒列表**（TLV 结构）：
每个盒结构为：`[box_type: u8][length: varint][payload: bytes]`。
当读取到 `box_type == 0x00` 时，表示 Header 元数据盒列表结束，紧接着即为第一帧。

## 4. 局部刷新协议与帧包格式

每个帧包以 1 字节 `frame_type` 开头：

```
0x00: KEY          (全屏关键帧，全部瓦片)
0x01: DELTA_TILES  (瓦片局部刷新)
0x02: DELTA_RECTS  (任意脏矩形局部刷新)
0x03: EMPTY        (空帧 / 纯时间戳步进)
0xFF: FRAME_END    (帧流结束哨兵)
```

### 4.1 任意脏矩形局部刷新 (DELTA_RECTS)

**核心原理**：当画面中只有一部分面积的内容发生变化时，在下一帧只用保存变化地方的画面数据。

包二进制布局：
1. `frame_type`: `0x02` (u8)
2. `pts`: `varint`（显示时间戳，ticks）
3. `rect_count`: `varint`（矩形数量，通常为 1）
4. 对于每个矩形：
   - `x`: `varint`（矩形左上角 X 坐标）
   - `y`: `varint`（矩形左上角 Y 坐标）
   - `w`: `varint`（矩形宽度）
   - `h`: `varint`（矩形高度）
   - `payload_len`: `varint`（压缩后载荷长度）
   - `payload`: `bytes`（压缩后的局部像素数据，解压后尺寸恰好为 `w × h × channels`）

**解码器行为**：
```python
patch = decompress(payload, shape=(h, w, channels))
if transform == XOR_DELTA:
    patch = canvas[y : y + h, x : x + w] ^ patch
canvas[y : y + h, x : x + w] = patch
```
无需触碰任何未变动的屏幕区域，局部更新耗时通常低于 0.1 毫秒。

### 4.2 瓦片网格局部刷新 (DELTA_TILES)

适合变动分散在多处的场景（例如多处字符同时闪烁）：
1. `frame_type`: `0x01` (u8)
2. `pts`: `varint`
3. `changed_tile_count`: `varint`（变化的瓦片数量）
4. `indices`: 差值 varint 列表。第 0 个存绝对索引，后续每个存 `idx[i] - idx[i-1] - 1`。
5. `payloads`: 依次存放每个变动瓦片的压缩数据（`[len: varint][bytes]`）。

### 4.3 纯时间戳空帧 (EMPTY)

当画面完全静止时（例如用户阅读网页或等待输入），生成空帧：
1. `frame_type`: `0x03` (u8)
2. `pts`: `varint`
3. **零图像数据载荷**！
整个包尺寸仅需 2 到 3 字节，大幅降低时间轴对齐或长时静止画面的文件开销。

## 5. 动态帧率 (VFR) 规范与优势

### 5.1 时间轴定义
DyV 采用绝对时钟滴答设计：
$$\text{时间（秒）} = \frac{\text{PTS}}{\text{Timescale}}$$

相邻两帧的显示时长为：
$$\Delta t_k = \frac{\text{PTS}_{k+1} - \text{PTS}_k}{\text{Timescale}}$$

### 5.2 对比传统固定帧率 (CFR)

| 场景 | 传统 CFR 机制 | DyV 动态帧率机制 |
| :--- | :--- | :--- |
| **界面静止 10 秒** | 强制写入 300~600 帧画面，即使无变化也有大量包头和空残差 | 无需写入任何帧，或仅写入 1 个 3 字节空帧 |
| **打字输入 (2~5 字符/秒)** | 传统视频保持 60 FPS 采样，冗余度高达 90% 以上 | 按击键事件生成帧（每次击键间隔约 200~500ms），帧率动态为 2~5 FPS |
| **突发窗口动效 (0.2 秒)** | 传统若为节约带宽设为 15 FPS，窗口动效出现明显卡顿 | 瞬间以 120 FPS（间隔 8.3ms）编码这 24 帧，动效极其丝滑细腻 |

## 6. 随机访问与关键帧索引 (Random Access & Seeking)

为了在长视频中实现秒级跳转而无需从第一帧完整回放，DyV 在文件末尾可选提供关键帧索引表：

### 尾部索引结构
```
[index_count: u32]
  [ordinal_0: u64][pts_0: u64][offset_0: u64]
  [ordinal_1: u64][pts_1: u64][offset_1: u64]
  ...
[total_frames: u64]
[index_offset: u64]
['DYVE': 4 字节]
```

**快速定位算法**：
1. 读取文件末尾 20 字节，验证 `'DYVE'` 魔数并获取 `index_offset`。
2. 查找关键帧索引，选取 $\text{PTS} \le \text{Target PTS}$ 的最大关键帧。
3. `seek(offset)` 直接跳至该关键帧重建完整参考画布。
4. 顺序快进解析中间少量的局部增量帧，即可瞬时完成任意时间点精准 Seek。
